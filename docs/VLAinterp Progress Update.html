Is There a Perception-to-Action Split Inside OpenVLA?
Alina Liu
1.1 The question
  • OpenVLA-7B maps a camera image and an instruction to a 7-DoF robot action, through a Llama-2 7B backbone with 32 layers.
  • Question: do early layers mainly encode the scene (perception) and later layers the action plan?
Question: is this the right question to start with, or is another direction more promising? - Even if it is true for OpenVLA, would it be true for other models

2.1 The simulation: LIBERO-Spatial
A simulated robot arm doing table-top tasks, run on OSC (one V100 GPU, 32 GB)
  • Tasks. 10 tasks, all in the same kind of scene: two black bowls, a plate, a ramekin, a cookie box, a cabinet. Each asks to move a specific bowl onto the plate, e.g. task 0: “pick up the black bowl between the plate and the ramekin and place it on the plate”.
  • Starting arrangements. Each task comes with 50 fixed starting arrangements, where the objects sit in slightly different places.
  • Episode. One attempt at one task from one starting arrangement.
  • How an episode runs. The model gets up to 220 steps. At each step it sees one camera image and gives one small movement. The episode ends as soon as the simulator detects the goal (bowl resting on the plate) = success. If 220 steps pass first = failure. OpenVLA's official evaluation uses it because the longest human demonstration for these tasks took 193 steps.
What the model sees: the first and last frame of a 20-step test episode of task 0.
2.2 Inside the model: one step
About 0.75 seconds per step on the V100
  1. Input: one camera image (256 × 256 pixels) and the instruction.
  2. Prepare the image exactly as OpenVLA's official test code does: turn it upside down (the camera is mounted upside down), compress and shrink it to 224 × 224, and crop to the central 90% (the model was trained on cropped images).
  3. Vision: two pretrained image networks (DINOv2 and SigLIP) split the image into a 16 × 16 grid of patches and turn each patch into 4096 numbers. These 256 “image tokens” are what the language model reads.
  4. Text: the instruction goes into a fixed sentence, “In: What action should the robot take to <instruction>? Out:”, about 30 text tokens.
  5. Model (Llama-2, 32 layers) reads all ~290 tokens and writes 7 output tokens, one at a time. One token per part of the action: move x, y, z; rotate roll, pitch, yaw; gripper.
  6. Tokens to numbers: each output token stands for one degree, and the number is from 0-256, they call this bins and it maps back to a real value (e.g. how far to move in x) using the ranges seen in training. The gripper value becomes open or close.
  7. Act: the 7-number command goes to the simulator, which moves the arm and renders the next image.

3.1 Run A: success rate
Does my setup reproduce OpenVLA's published result?
  • Episodes: all 10 tasks × starting arrangements 0–4 = 50 episodes.
  • Each episode: a fresh simulator is created, set to that starting arrangement, 10 waiting steps, then up to 220 model steps as on 2.1.
  • Model call: OpenVLA's own prediction function, with the official image preparation from 2.2. Nothing inside the model is recorded.
  • Recorded per episode: task, starting arrangement, instruction, success or failure, number of steps, and a video.
  • Result: success rate overall and per task, compared with the 84.7% OpenVLA reports for LIBERO-Spatial.

  • From scores to probabilities: of the 32,064 scores, keep the 256 that belong to action bins (vocabulary entries 31744–31999) and turn them into probabilities that add up to 1.

What it does
  • Runs the same 50 episodes as run A.
  • At every step, applies the logit lens at all 33 layers, for each of the 7 action tokens.
  • Also saves the hidden states and simulator values from 2.3, for run C.
  • Two checks stop the run if they fail: my recording path must give exactly the same action as OpenVLA's own function, and the lens at the last layer must pick exactly the bin the model output.
  • Result: agreement, bin distance and KL by layer, for each action part.
  • The lens can miss information. Middle layers may hold the answer in a form the output layer cannot read directly, so they look “empty” when they are not.

3.3 Run C: Looking at perception using linear probes
A tentative next step. I am not sure yet this is the right approach
Why
  • The logit lens (Run B) only shows when the action appears. It cannot show where the model keeps track of the scene, because the model never outputs where things are.
The idea
  • At each layer, check whether the model's internal numbers already “contain” where the gripper and the bowl are, by testing if a simple formula can read those positions back out.
  • If positions can be read out at early layers and the action only at later layers, that would hint at a perception → action split.
Questions
  • Being able to read something out does not mean the model actually uses it.
  • Which scene details to test: the gripper and the carried bowl move, but most objects stay put.
  • Whether another method would look at perception better.
